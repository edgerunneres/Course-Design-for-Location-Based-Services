# 课程设计成果架构对照

老师提示图的关键点是“专题 POI API 服务”和“引用专题 API 的应用”分离，同时应用集成公众地图服务。本项目符合该结构。

## 对照关系

| 提示图元素 | 本项目实现 |
| --- | --- |
| 1 专题 POI API 服务 | `server/server.js`，REST 风格 API，提供 POI 查询、详情、CRUD、注册登录、APIKEY、限速和错误码 |
| 数据存储 | `server/data/db.json`，首次由 `poi-seed.json` 初始化；数据来自老师提供的全国文保单位 Excel |
| 4 专题移动应用 | `miniprogram` 微信小程序，包含地图、详情、账户、维护页面 |
| POI API 请求/响应 | 小程序 `utils/api.js` 统一访问 `/api/v1` 接口 |
| MAP API 请求/响应 | 微信小程序 `map` 组件和 `wx.getLocation` 集成公众地图与定位能力 |
| 公众用户能力 | 注册、登录、APIKEY 获取、个人资料维护、查询 POI |
| 内部维护角色 | 维护页登录 admin 后执行单项新增、修改、删除 |

## 结论

本项目实际包含两个应用/服务：

1. 后端专题 POI API 服务：负责数据、权限、安全、JSON 接口。
2. 微信小程序移动应用：负责地图呈现、位置授权、POI 查询和维护演示。

因此项目结构与课程设计提示图一致。当前没有额外实现 Web 网站或桌面应用，因为课程要求客户端类型不限，微信小程序已经覆盖“专题移动应用”路径。
